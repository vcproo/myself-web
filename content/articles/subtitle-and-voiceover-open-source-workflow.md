个人独立做视频，如果每一期都要手动听打字幕、逐句对时间轴，很容易在第三四期就因为精力耗尽而断更。现在开源社区在语音识别（ASR）和文本转语音（TTS）两个方向都已经非常成熟，普通家用电脑就能在本地免费跑出相当不错的效果。

这篇整理一套我实测下来最稳妥、不折腾的字幕与音频处理组合思路。

## 录音转字幕：本地 Whisper + AI 错别字校对

开源的 Whisper 模型对日常普通话口播的识别率已经很高，唯一的小遗憾是偶尔会把英文开源项目名或专业缩写听成同音汉字（比如把 `Remotion` 识别成同音词）。

我现在的固定做法是分两步走：

1. 先用本地 Whisper 工具直接导出带时间轴的 `.srt` 字幕文件；
2. 把 `.srt` 内容连同原本的文案大纲一起发给大模型，让它**在不改动任何时间轴数字的前提下，仅修正专有名词和同音错别字**。

```prompt
下面是一份自动语音识别生成的 SRT 字幕文本。请在【绝对不修改序号与时间轴格式、不增删字幕行数】的前提下，结合我提供的专有名词列表，修正其中的同音错别字与大小写错误，并直接输出完整可用的 SRT 内容。

本期涉及的专有名词参考：Remotion, GitHub, Node.js, Ollama, Markdown

原始 SRT 字幕内容：
[粘贴 SRT 内容]
```

## 批量转换音视频格式的常用命令

做视频素材整理时，经常需要从录屏视频里单独提取干净的音频轨交给识别工具，备一行 `ffmpeg` 命令比打开大型剪辑软件导出快得多：

```bash
# 从视频文件中快速提取 16kHz 单声道 WAV 音频（最适合语音识别模型处理，体积小速度快）
ffmpeg -i input-video.mp4 -vn -acodec pcm_s16le -ar 16000 -ac 1 output-audio.wav
```

把这些零碎耗时的小环节固定成顺手的脚本与模板后，你就可以把宝贵的注意力重新放回选题实测和内容本身上。
